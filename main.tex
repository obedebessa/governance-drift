% ------------------------- abstract ----------------------------------
\noindent\textbf{\textit{Abstract}---Configuration drift compares desired and observed configuration. We define \emph{governance drift}: divergence between operational reality and the state, policy context, authorization basis, intent, evidence, or environment assumptions under which that reality was approved. A resource can match Git while violating superseding policy, relying on expired authority, running an unapproved artifact, or reflecting an unauthorized rollback. We contribute a six-class taxonomy; an approved-snapshot model with time-indexed contexts and a governance-distance vector; counterexamples and a dependency result showing why configuration equality cannot decide governance consistency; a cumulative evidence-tier architecture; an executed closed-world study; and a repeated Kubernetes/GitOps laboratory. In the modeled world, normalized configuration comparison detects one of nine scenarios. Adding policy, authorization, lineage, and environment evidence yields a strict detectability staircase, while an unnormalized comparator alarms on 71\% of control events. In the pinned Kind/Flux/Kyverno laboratory, we repeated each scenario 20 times with randomized polling phase at 0.5-, 2-, and 10-second cadences. The evaluator detected 538 of 540 cadence runs; both misses were transient S1 configuration drift at slower cadences. Conditional classification accuracy was 100\% (538/538). Across 20 balanced benign-change windows and 543 polls, it raised no alarm. Actuation, onset-to-detection, injection-to-detection, and time-to-evidence are reported separately. This bounded execution demonstrates the realizability of the proposed classes and evaluator on one pinned Kubernetes/GitOps laboratory with file-backed approval and environment streams; it does not estimate prevalence, production effectiveness, stream-loss reliability, or transfer beyond this stack.}
